issus du moteur risque, avec les exigences suivantes :

A) ORDER MANAGEMENT — BRACKET / SYNTHETIC BRACKET
   - Entrée long via ordre market ou limit configurable
   - Protection via stop dynamique (Trailing Stop)
   - Prise de profit via Profit Taker
   - Si Alpaca ne supporte pas nativement “bracket + trailing stop” exactement
     comme souhaité, implémenter un modèle “synthetic bracket” :
       1. soumettre le parent entry
       2. attendre fill / partial fill
       3. créer les ordres enfants OCO : trailing stop + take profit

B) PAPER / LIVE ONE-CLICK TOGGLE
   - un seul flag de config / CLI
   - même code path
   - mêmes logs
   - mêmes tables d’audit
   - seul le broker endpoint / mode change

C) EXECUTION BANK-GRADE / INSTITUTIONAL FEATURES
   Le module doit inclure au minimum :
   - pre-trade validation (market hours, symbole, qty > 0, dry-run)
   - idempotency par `(run_id, symbol, side, intent_type)`
   - order lifecycle state machine
   - retry réseau borné avec logs
   - partial fill handling
   - cancel / replace pour ordres enfants si qty change
   - end-of-day reconciliation broker vs DB
   - kill switch / circuit halt
   - shared audit trail paper/live
   - observabilité claire par run, order, event, fill
   - reprise safe après crash/redémarrage
   - mode dry-run sans appel broker
   - support d’un “target execution plan” depuis `portfolio_targets`

D) ALIGNEMENT AVEC LE PROJET EXISTANT
   - la source d’exécution est `portfolio_targets`
   - ne pas dupliquer la logique de sizing / risk déjà présente
   - ne pas déplacer la logique risque dans l’executor

     1. chargement des cibles
     2. génération d’intentions d’ordre
     3. soumission / suivi / audit

class ProductionExecutor:
    def __init__(
        self,
        config: ExecutionConfig,
        repo: ExecutionRepository,
        broker: AlpacaTradingClient,
    ) -> None: ...

    def execute_run(self, trade_date: date | None = None, run_id: str | None = None) -> dict[str, int]:
        """
        Pipeline :
        1. Charger les targets depuis portfolio_targets
        2. Construire les entry intents
        3. Filtrer les intents déjà soumis (idempotency)
        4. Vérifier market clock / RTH si requis
        5. Soumettre les ordres d’entrée
        6. Poller jusqu’à FILLED / timeout / terminal state

class ProductionExecutor:
    def __init__(
        self,
        config: ExecutionConfig,
        repo: ExecutionRepository,
        broker: AlpacaTradingClient,
    ) -> None: ...

    def execute_run(self, trade_date: date | None = None, run_id: str | None = None) -> dict[str, int]:
        """
        Pipeline :
        1. Charger les targets depuis portfolio_targets
        2. Construire les entry intents
        3. Filtrer les intents déjà soumis (idempotency)
        4. Vérifier market clock / RTH si requis
        5. Soumettre les ordres d’entrée
        6. Poller jusqu’à FILLED / timeout / terminal state
        7. Si entry filled ou partial filled :
             créer les enfants take-profit + trailing stop
        8. Persister orders, fills, events
        9. Reconciliation broker vs DB si activée
        10. Retourner un résumé métrique
        """
