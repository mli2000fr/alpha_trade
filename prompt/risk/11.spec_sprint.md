## 2. Design retenu

## 2.1 Support `.env` dans le launcher Windows

### `scripts/windows/protection_watcher_launcher.ps1`

Le launcher PowerShell est devenu le point d’entrée unique de l’exploitation Windows.

Il sait désormais :

- résoudre Python ;
- charger un fichier `.env` ;
- charger un secret store Windows ;
- injecter les secrets dans le process ;
- puis lancer `run_execution_protection_watch.py`.

### Recherche des fichiers

Si rien n’est fourni explicitement, le launcher essaie automatiquement :

#### `.env`
- `scripts/windows/protection_watcher.env`
- `.env`
- `.env.watcher`

#### secret store
- `artifacts/windows_secrets/protection_watcher.secrets.json`
- `scripts/windows/protection_watcher.secrets.json`
- `%ProgramData%\AlphaTrade\protection_watcher.secrets.json`
- `%APPDATA%\AlphaTrade\protection_watcher.secrets.json`

### Priorité retenue

Le launcher charge :

1. le `.env` ;
2. puis le secret store.

Donc le secret store peut volontairement **surcharger** les valeurs du `.env`.

## 2.2 Secret store Windows : choix DPAPI

### `scripts/windows/protection_watcher_secrets.ps1`

Plutôt que d’introduire une dépendance externe lourde, la solution retenue est un **secret store JSON chiffré en DPAPI** via Windows.

Ce store permet de protéger les secrets :

- `LOGIN_DB`
- `PASSWORD_DB`
- `ALPACA_API_KEY`
- `ALPACA_SECRET_KEY`

et plus largement toute liste de noms passée au script.

### Pourquoi DPAPI ?

Avantages :

- natif Windows ;
- pas de dépendance Python supplémentaire ;
- pas besoin de base ou coffre externe ;
- compatible exploitation PowerShell / Task Scheduler / NSSM.

### Scopes disponibles

- `CurrentUser`
- `LocalMachine`

### Usage recommandé

#### `CurrentUser`
À utiliser quand :

- la tâche tourne en utilisateur interactif ;
- le watcher est lancé sous votre compte Windows ;
- vous voulez limiter le déchiffrement à ce compte.

#### `LocalMachine`
À utiliser quand :

- le watcher tourne comme service machine ;
- le compte d’exécution peut varier ;
- par exemple avec NSSM / `SYSTEM`.

⚠️ Avec `LocalMachine`, il faut **restreindre les ACL du fichier** : le chiffrement devient lié à la machine, pas à un seul utilisateur.

## 2.5 Statut heartbeat rouge / orange / vert dans l’IHM

### `ihm/components/status_badges.py`

Ajout de :

- `classify_heartbeat_freshness(...)`
- `heartbeat_badge(...)`

### Règles retenues

Le heartbeat est évalué à partir de :

- `last_heartbeat_at`
- `heartbeat_interval_seconds`
- `service_status`

#### Vert — `FRAIS`
si l’âge du heartbeat est `<= 1.25 x interval`

#### Orange — `À SURVEILLER`
si l’âge du heartbeat est `<= 2.5 x interval`

#### Rouge — `STALE`
si l’âge du heartbeat est `> 2.5 x interval`

#### Rouge — `KO` / `ARRÊTÉ`
si le service est déjà en statut `FAILED`, `ERROR` ou `STOPPED`

#### Orange — `INCONNU`
si on ne peut pas classifier proprement :

- pas de timestamp ;
- intervalle manquant ;
- timestamp invalide.

## 3. À quoi servent les fichiers `*.ps1` ?

Voici le rôle exact de chaque script PowerShell livré dans `scripts/windows/`.

## 3.1 `protection_watcher_launcher.ps1`

### À quoi il sert
C’est le **point d’entrée d’exécution réel** du watcher côté Windows.

Il :

- charge la config runtime (`.env` / secret store) ;
- résout Python ;
- positionne le bon répertoire ;
- lance le watcher Python.

### Comment l’utiliser
À la main pour tester un run :

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_launcher.ps1 -Mode once -Account default
```

Avec `.env` explicite :

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_launcher.ps1 -Mode service -EnvFilePath "C:\AlphaTrade\protection_watcher.env"
```

Avec secret store explicite :

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_launcher.ps1 -Mode service -SecretStorePath "$env:APPDATA\AlphaTrade\protection_watcher.secrets.json"
```

### Quand l’utiliser
- pour tester manuellement ;
- pour debug un problème de démarrage ;
- comme brique appelée par Task Scheduler ou NSSM.

---

## 3.2 `protection_watcher_secrets.ps1`

### À quoi il sert
Il crée, supprime ou inspecte le **secret store Windows DPAPI**.

### Comment l’utiliser
#### Sauvegarde interactive

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_secrets.ps1 -Action Save -DpapiScope CurrentUser
```

#### Sauvegarde depuis les variables d’environnement déjà chargées

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_secrets.ps1 -Action Save -DpapiScope CurrentUser -FromEnvironment
```

#### Métadonnées

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_secrets.ps1 -Action ShowMetadata
```

#### Suppression

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\protection_watcher_secrets.ps1 -Action Remove
```

### Quand l’utiliser
- lors du setup initial ;
- à chaque rotation de credentials ;
- si vous ne voulez pas garder les secrets en clair dans un `.env`.

---

## 3.3 `install_protection_watcher_task.ps1`

### À quoi il sert
Il installe le watcher dans **Windows Task Scheduler**.

### Comment l’utiliser

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install_protection_watcher_task.ps1 -TaskName "AlphaTrade-ProtectionWatcher" -FrequencyMinutes 5 -Account default -Mode once
```

Avec secret store :

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install_protection_watcher_task.ps1 -TaskName "AlphaTrade-ProtectionWatcher" -FrequencyMinutes 5 -Account default -SecretStorePath "$env:APPDATA\AlphaTrade\protection_watcher.secrets.json"
```

### Quand l’utiliser
- si vous voulez un **polling périodique simple** ;
- si le modèle d’exploitation préféré est `once` toutes les X minutes ;
- si vous ne voulez pas d’un service long-lived.

---

## 3.4 `uninstall_protection_watcher_task.ps1`

### À quoi il sert
Il supprime la tâche planifiée.

### Comment l’utiliser

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\uninstall_protection_watcher_task.ps1 -TaskName "AlphaTrade-ProtectionWatcher"
```

### Quand l’utiliser

- avant une réinstallation propre avec autre config.

---

## 3.5 `install_protection_watcher_service_nssm.ps1`

### À quoi il sert
Il installe le watcher comme **service Windows supervisé par NSSM**.

### Comment l’utiliser

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install_protection_watcher_service_nssm.ps1 -NssmExePath "C:\tools\nssm\win64\nssm.exe" -ServiceName "AlphaTradeProtectionWatcher" -Account default -StartAfterInstall
```

Avec store `LocalMachine` :

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install_protection_watcher_service_nssm.ps1 -NssmExePath "C:\tools\nssm\win64\nssm.exe" -ServiceName "AlphaTradeProtectionWatcher" -Account default -SecretStorePath "$env:ProgramData\AlphaTrade\protection_watcher.secrets.json" -StartAfterInstall
```

### Quand l’utiliser
- si le watcher doit rester **toujours vivant** ;
- si vous voulez supervision, restart et logs de service ;
- si vous préférez une architecture service plutôt qu’un polling scheduler.

---

## 3.6 `uninstall_protection_watcher_service_nssm.ps1`

### À quoi il sert
Il supprime le service NSSM.

### Comment l’utiliser

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\uninstall_protection_watcher_service_nssm.ps1 -NssmExePath "C:\tools\nssm\win64\nssm.exe" -ServiceName "AlphaTradeProtectionWatcher"
```

### Quand l’utiliser
- pour retirer le service ;
- avant une réinstallation différente ;
- si vous migrez de NSSM vers Task Scheduler ou inversement.

## 4. Quel mode choisir en pratique ?

## 4.1 Cas simple / robuste : Task Scheduler + `once`

À privilégier si :

- vous voulez quelque chose de simple ;
- vous acceptez un scan toutes les 5 minutes ;
- vous voulez minimiser la complexité ops.

## 4.2 Cas service temps réel-ish : NSSM + `service`

À privilégier si :

- vous voulez un process long-lived ;
- vous voulez un heartbeat régulier ;
- vous avez déjà une supervision Windows / NSSM.

## 4.3 Cas dev / debug : launcher direct

À privilégier si :

- vous testez localement ;
- vous changez souvent la config ;
- vous voulez lancer un one-shot à la main.
