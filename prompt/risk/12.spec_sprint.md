## 1. Objectif

La page `Supervision Ops` supervisait déjà :

- l’état des services ;
- les heartbeats stale ;
- les derniers runs critiques ;
- les alertes synthétiques.

L’objectif de cette passe était d’aller un cran plus loin en ajoutant un **pilotage ops limité et sûr** depuis l’IHM, sans transformer l’IHM en remplaçant dangereux du packaging Windows d’exploitation.

Concrètement, il fallait permettre depuis l’IHM :

1. un **`run watcher once`** ;
2. un **stop contrôlé** d’un watcher local lancé par l’IHM ;
3. un **start / restart contrôlé** d’un watcher local lancé par l’IHM ;
4. des **garde-fous explicites** pour éviter de dupliquer ou casser un service Windows packagé via Task Scheduler / NSSM.

---

## 2. Design retenu

## 2.1 Séparer clairement « pilotage local IHM » et « exploitation Windows packagée »

Le point clé est le suivant :

- **l’IHM ne pilote que des processus qu’elle a elle-même lancés** ;
- **les scripts PowerShell restent responsables** de l’installation, du packaging machine, du bootstrap des secrets Windows et du contrôle des services NSSM / tâches planifiées.

Donc cette passe **n’ajoute pas** dans l’IHM :

- d’installation Task Scheduler ;
- de redéploiement NSSM ;
- de manipulation des secrets DPAPI ;
- de restart machine-wide d’un service Windows existant.

Elle ajoute uniquement un **runtime local IHM**, volontairement borné.

---

## 2.2 Nouveau runtime watcher côté IHM

### Fichier : `C:\Users\MLI\PycharmProjects\alpha_trade\ihm\services\watcher_runtime.py`

Un nouveau service IHM encapsule le pilotage local du watcher :

- `build_watcher_command(...)`
- `launch_watcher_once(...)`
- `start_local_watcher_service(...)`
- `stop_local_watcher_service(...)`
- `restart_local_watcher_service(...)`
- `list_active_watcher_runs(...)`

Deux types de runs locaux sont distingués :

- `execution_protection_watch_once`
- `execution_protection_watch_service_local`

Ces runs appellent directement :

- `python -u run_execution_protection_watch.py --mode once ...`
- ou `python -u run_execution_protection_watch.py --mode service ...`

avec l’environnement reconstruit depuis l’IHM.

### Pourquoi ce choix ?

Parce qu’il permet :

- de **réutiliser le code watcher existant** ;
- de **ne pas dépendre des scripts `*.ps1` pour un simple pilotage local** ;
- tout en **refusant de se faire passer pour le vrai packaging d’exploitation**.

## 2.3 Réutilisation du registre de processus IHM

### Fichier : `C:\Users\MLI\PycharmProjects\alpha_trade\ihm\services\process_registry.py`

Le registre gérait déjà les runs pipelines/workflows IHM.

Il expose maintenant un helper plus générique :

- `start_managed_run(...)`

Ce helper factorise :

- création du répertoire d’artefacts ;
- lancement du sous-processus ;
- capture `stdout` / `stderr` ;
- suivi live ;
- arrêt via `stop_pipeline_run(...)` ;
- historisation.

Le runtime watcher local repose dessus.

### Effet

Les runs watcher lancés depuis `Supervision Ops` sont :

- visibles dans les **runs IHM actifs** ;
- arrêtables comme les autres runs gérés par l’IHM ;
- historisés dans `artifacts/ihm_pipeline_runs/...`.

## 2.4 Garde-fous métiers / ops

### Fichier : `C:\Users\MLI\PycharmProjects\alpha_trade\ihm\services\ops_supervision.py`

Ajout de `build_watcher_control_state(...)`.

Cette fonction consolide :

- la santé persistée du watcher (`execution_protection_watch_service`) ;
- les runs locaux actifs vus par le registre IHM.

Elle produit notamment :

- `local_service_active`
- `local_service_run_id`
- `local_once_active`
- `fresh_service_detected`
- `external_fresh_service_detected`
- `guardrail_messages`

### Règle principale

Si l’IHM voit :

- un **heartbeat watcher frais**,
- mais **aucun process local IHM actif correspondant**,

alors elle considère qu’il s’agit probablement d’un watcher déjà piloté par le packaging Windows externe.

Dans ce cas, elle :

- **bloque par défaut les démarrages locaux** ;
- affiche un message d’alerte expliquant le risque de doublon ;
- n’autorise un lancement local qu’après un **acknowledgement explicite** + une **override explicite**.

### Stop contrôlé

Le bouton stop n’accepte que les runs dont le `step_key` est :

- `execution_protection_watch_service_local`

Donc :

- un service NSSM existant n’est **pas** stoppé par erreur depuis l’IHM ;
- un vieux run historique non local n’est **pas** stoppé ;
- l’IHM ne manipule que ce qu’elle a lancé elle-même.

## 2.5 Intégration dans la page `Supervision Ops`

### Fichier : `C:\Users\MLI\PycharmProjects\alpha_trade\ihm\pages\supervision_ops.py`

La page contient désormais un bloc dédié :

- `🎛️ Pilotage watcher depuis l'IHM`

Ce bloc affiche :

- l’état du service local IHM ;
- le `run_id` du service local ;
- le `run_id` d’un éventuel `run once` local ;
- les messages de garde-fous ;
- une confirmation opérateur obligatoire ;
- une option d’override exceptionnel ;
- les paramètres runtime locaux (`limit`, `interval`, `idle`, `heartbeat`) ;
- les boutons d’action.

### Boutons ajoutés

- `▶️ Run watcher once`
- `▶️ Démarrer service local IHM` / `♻️ Restart service local IHM`
- `⏹️ Stop service local IHM`

### Désactivation automatique

Les boutons sont désactivés selon plusieurs cas :

- confirmation opérateur non cochée ;
- `run once` local déjà actif ;
- service local déjà actif pour le bouton `run once` ;
- service watcher externe détecté avec heartbeat frais, sans override explicite.

## 3. Ce que l’IHM peut faire maintenant

L’IHM peut maintenant :

- lancer un **watcher ponctuel** (`once`) ;
- lancer un **service local watcher** lié à la session/processus IHM ;
- arrêter ce **service local** ;
- relancer ce **service local** ;
- suivre ces runs dans le tableau des runs actifs.

---

## 4. Ce que l’IHM ne fait volontairement toujours pas

L’IHM ne remplace **pas** encore les scripts `*.ps1` pour :

- installer / désinstaller la tâche planifiée Windows ;
- installer / désinstaller le service NSSM ;
- gérer les fichiers DPAPI / secret store ;
- garantir un redémarrage automatique machine-wide au boot ;
- exploiter un compte Windows de service dédié ;
- administrer proprement un service existant hors de la session IHM.

En résumé :

- **oui**, on peut maintenant faire un pilotage ops local depuis l’IHM ;
- **non**, cela ne remplace pas le packaging Windows d’exploitation ;
- **oui**, les fichiers `*.ps1` restent nécessaires pour la mise en production robuste et persistante.

---

## 5. Pourquoi les scripts `*.ps1` restent nécessaires

Les scripts PowerShell gardent une responsabilité différente :

### `protection_watcher_launcher.ps1`

- bootstrap Windows ;
- chargement `.env` / secret store ;
- résolution Python ;
- point d’entrée uniforme d’exploitation.

### `install_protection_watcher_task.ps1`

- installation idempotente dans **Task Scheduler** ;
- redémarrage périodique / autonome hors session IHM.

### `install_protection_watcher_service_nssm.ps1`

- installation comme **service Windows** via NSSM ;
- démarrage automatique au boot ;
- gestion standard d’exploitation Windows.

### `protection_watcher_secrets.ps1`

- préparation du **secret store DPAPI** ;
- sécurisation des secrets DB / broker côté Windows.

Autrement dit :

- l’IHM = **pilotage local / supervision / dépannage rapide** ;
- PowerShell = **packaging d’exploitation / persistance / sécurité machine**.

## 8. Conclusion

La page `Supervision Ops` est maintenant passée de la **pure observation** à un **pilotage ops local maîtrisé**.

Le compromis retenu est volontairement prudent :

- assez puissant pour lancer / arrêter / relancer un watcher depuis l’IHM ;
- assez borné pour ne pas écraser silencieusement l’exploitation Windows existante.

C’est la bonne étape intermédiaire entre :

- **supervision seule** ;
- et un futur éventuel **run control complet** plus industrialisé.

Si on veut aller plus loin ensuite, les évolutions naturelles seraient :

1. afficher l’historique dédié des runs watcher IHM ;
2. afficher les logs live du watcher local dans la page ;
3. ajouter un mode d’intégration explicite avec NSSM / Task Scheduler ;
4. ajouter un verrouillage par rôle opérateur si plusieurs utilisateurs IHM pilotent le même environnement.
