## 1. Objectif du Sprint 1

Le Sprint 1 vise à rendre le module `risk_management` :

- **point-in-time safe** ;
- alimenté par une **source de vérité compte** ;
- réellement protégé par un **circuit breaker actif** ;
- simplifié autour d’un **schéma canonique unique** ;
- cohérent avec une politique **ATR absent = rejet**.

Le Sprint 1 ne vise pas encore :

- une refonte IHM complète ;
- une corrélation post-sizing avancée ;
- une industrialisation complète de Kelly ;
- une refonte du moteur d’exécution.

---

## 2. Périmètre fonctionnel

### 2.1 Inclus

   - candidats ;

## 3. Contrats de données cibles

## 3.1 Lecture candidats

### Source cible
`stock_scores_history`

### Règle
- lecture sur `snapshot_date = trade_date`
- filtrage `is_candidate = 1`
- conservation du `score_source` et des métadonnées walk-forward

### Sortie attendue
Le modèle candidat doit porter au minimum :
- `symbol`
- `sector`
- `score_used`
- `score_source`
- `snapshot_date`
- métadonnées walk-forward / calibration si présentes.

---

## 3.2 Lecture prix / ATR

### Source cible
`stock_bars_daily`

### Règle
- prix le plus récent avec `date <= trade_date`
- calcul ATR à partir des dernières observations bornées à `trade_date`
- conservation de `price_asof_date` et `atr_asof_date`

### Politique Sprint 1
- ATR absente ou non calculable = **rejet**
- plus de fallback `equal_weight` en production

## 5. Critères d’acceptation Sprint 1

Le Sprint 1 est considéré comme terminé si :

1. un run à date historique ne lit aucune donnée future ;
2. le module lit les candidats depuis `stock_scores_history` ;
3. le module lit prix/ATR/rendements avec borne `trade_date` ;
4. l’equity utilisée est traçable via `account_risk_snapshots` ;
5. le circuit breaker peut réellement empêcher un run de produire des positions ;
6. ATR absente entraîne un rejet explicite ;
7. `risk_decisions` et `portfolio_targets` sont écrites via un seul schéma canonique ;
8. les tests ciblés Sprint 1 passent.

---

## 6. Risques d’intégration

### Risque 1 — `stock_scores_history` non alimentée
Impact : impossible de construire un run PIT.

Réponse Sprint 1 :
- erreur claire plutôt que fallback silencieux.

### Risque 2 — snapshot compte absent en non `dry-run`
Impact : equity et circuit breaker non fiables.

Réponse Sprint 1 :
- blocage explicite du run.

### Risque 3 — contrat aval `execution_engine`
Impact : l’exécution continue à ne consommer qu’un sous-ensemble des champs.

Réponse Sprint 1 :
- enrichir `portfolio_targets` sans casser le chargement aval existant.
