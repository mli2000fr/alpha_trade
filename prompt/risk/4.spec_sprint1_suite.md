## 2. Modifications réalisées

## 2.1 Lectures point-in-time

Dans `risk_management/db_io.py`, j’ai introduit des lectures PIT explicites :

- `load_candidates_asof(trade_date)`
- `load_prices_asof(symbols, trade_date, atr_window)`
- `load_predictions_asof(symbols, trade_date)`
- `load_win_rates_asof(symbols, trade_date)`
- `load_return_matrix_asof(symbols, trade_date, lookback_days)`
- `load_account_risk_snapshot(account_id, trade_date)`

### Effets concrets

- les candidats sont désormais lus depuis `stock_scores_history` à `snapshot_date = trade_date` ;
- les prix et ATR sont bornés à `trade_date` ;
- la matrice de rendements est bornée à `trade_date` avec un chargement **top N par symbole** ;
- les prédictions ML futures ne sont plus visibles par un run historique ;
- les win rates / métriques ML futures ne sont plus visibles non plus.

## 2.2 Snapshot compte et circuit breaker

Dans `risk_management/cli.py` :

- suppression de la logique actuelle d’equity enrichie via le cumul global des dividendes ;
- chargement du snapshot via `account_risk_snapshots` ;
- construction d’un vrai `PnLSnapshot` ;
- branchement du `PortfolioBuilder` avec ce snapshot.

### Politique retenue

- **non `dry-run`** : absence de snapshot compte => **erreur explicite** ;
- **`dry-run`** : fallback possible sur `--account-equity`, avec log d’avertissement.

### Effet métier

Le circuit breaker n’est plus purement décoratif :
- il peut maintenant être alimenté par une vraie equity et un vrai PnL journalier ;
- il peut bloquer réellement la construction de positions.
