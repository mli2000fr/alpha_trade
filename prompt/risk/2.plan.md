## 1. Objectif du plan

Ce document transforme l’audit `prompt/risk/1.audit.md` en **cible opérationnelle** pour le module `risk_management`.

Contexte retenu :

- stratégie **swing trading** ;
- univers **actions US daily** ;
- portefeuille **principalement cash, long-only** ;
- historique possible de **jusqu’à 10 ans par symbole** ;
- **reset des tables autorisé**, donc pas de compromis inutile pour conserver la rétrocompatibilité.

---

## 2. Principes directeurs

La cible doit respecter 6 principes simples.

### 2.1 Point-in-time strict

Toutes les lectures doivent être cohérentes avec `trade_date` :

- candidats ;
- prix ;
- ATR ;
- rendements ;
- probabilités ML ;
- métriques de calibration / win rate ;
- état du compte.

### 2.2 Long-only cash explicite

Le moteur doit assumer clairement le cas d’usage principal :

- pas de levier ;
- pas de short ;
- exposition brute cible `<= 1.0` ;
- sizing pensé pour préserver le capital.

### 2.3 Sizing de risque explicable

Le moteur doit pouvoir expliquer précisément, pour chaque symbole :

- pourquoi il a été retenu ou rejeté ;
- quel budget de risque a été consommé ;
- quel stop implicite est associé ;
- quel poids et quel notionnel ont été construits.

### 2.4 Transmission propre vers l’exécution

`portfolio_targets` doit devenir la **vérité canonique** pour `execution_engine`, pas seulement une table de sortie minimale.

### 2.5 Schéma simple et unique

Après reset, il faut viser :

- un seul schéma SQL cible ;
- aucune cascade V1 / V2 / V3 / V4 ;
- aucune logique de compatibilité héritée.

### 2.6 Observabilité native

Chaque run doit être pilotable depuis :

- les tables d’audit ;
- le résumé métier ;
- l’IHM.

## 3.2 Couche 1 — Snapshots as-of

Cette couche garantit la cohérence temporelle.

### Entrées cibles

#### A. Snapshot candidats
Source recommandée : `stock_scores_history`

Règle cible :
- lecture sur `snapshot_date = trade_date`
- plus de lecture directe du snapshot courant `stock_scores` pour un run historique

#### B. Snapshot marché
Source recommandée : `stock_bars_daily`

Règle cible :
- dernier prix avec `date <= trade_date`
- ATR calculé uniquement à partir d’observations `<= trade_date`
- matrice de rendements bornée à `trade_date`

#### C. Snapshot ML
Sources recommandées :
- `model_predictions`
- tables métriques / calibration ML

Règle cible :
- `prediction_date <= trade_date`
- métriques de performance / calibration strictement antérieures ou égales à `trade_date`

#### D. Snapshot compte
Nouvelle source cible recommandée : `account_risk_snapshots`

Cette table doit contenir au minimum :
- `account_id`
- `trade_date`
- `cash`
- `equity`
- `buying_power`
- `high_watermark`
- `daily_realized_pnl`
- `daily_unrealized_pnl`
- `created_at`

### Pourquoi c’est la bonne cible

Cette couche supprime les ambiguïtés actuelles sur :
- les reruns historiques ;
- le circuit breaker ;
- l’equity réelle ;
- les métriques ML utilisées pour le sizing Kelly.

## 3.3 Couche 2 — Repository risque

Le repository cible doit devenir un **repository PIT unifié**.

### Responsabilités cibles

Le repository doit exposer des méthodes explicites, de type :

- `load_candidates_asof(trade_date)`
- `load_prices_asof(symbols, trade_date, atr_window)`
- `load_return_matrix_asof(symbols, trade_date, lookback_days)`
- `load_predictions_asof(symbols, trade_date)`
- `load_win_rates_asof(symbols, trade_date)`
- `load_account_risk_snapshot(account_id, trade_date)`

### Règles de conception

- les bornes temporelles doivent être dans la requête, pas dans la logique appelante ;
- les méthodes doivent renvoyer aussi les **dates effectives source** utiles à l’audit ;
- la lecture de la matrice de rendements doit être **top N par symbole**, pas un `LIMIT` global.

### Décision importante

Le repository ne doit plus compenser les insuffisances de schéma par des heuristiques implicites.

Exemples :
- pas d’equity recalculée localement depuis un cumul global de dividendes ;
- pas de lecture “dernier run disponible” sans borne temporelle ;
- pas de fallback silencieux vers des données futures.

## 3.4 Couche 3 — Moteur de décision

Cette couche reste centrée sur `PortfolioBuilder`, mais avec un contrat plus clair.

### Pipeline cible

1. charger et enrichir les candidats ;
2. calculer le score de conviction ;
3. appliquer le pré-filtre de corrélation ;
4. calculer le sizing ;
5. appliquer les contraintes portefeuille ;
6. calculer les champs de risque finaux ;
7. persister décisions + cibles + résumé.

### Politique cible recommandée

#### Conviction
- conserver un score de conviction simple et lisible ;
- utiliser le ML comme surcouche, pas comme vérité autonome ;
- neutraliser proprement les cas sans prédiction.

#### Sizing principal
- **ATR sizing par défaut** ;
- ATR documenté et stable ;
- ATR absent en production : **rejet** plutôt que fallback `equal_weight`.

#### Kelly
- **désactivé par défaut** ;
- activable seulement en mode expérimental / validé ;
- nécessite des métriques ML strictement PIT et calibrées.

#### Corrélation
- conserver le filtre pairwise greedy comme pré-filtre ;
- ajouter ensuite une vue run-level sur la concentration résiduelle.

#### Circuit breaker
- alimenté par `account_risk_snapshots` ;
- pas de pseudo-protection inactive.

## 5. Paramètres cibles adaptés au cas d’usage

## 5.1 Profil retenu

Je pars sur le profil suivant :

- swing trading daily ;
- portefeuille cash ;
- recherche de robustesse avant agressivité ;
- portefeuille concentré mais diversifié ;
- exécution sur actions US liquides.

---

## 5.2 Paramètres cœur portefeuille

### Paramètres recommandés de base

- `account_equity` : piloté par `account_risk_snapshots`
- `risk_per_trade_pct` : **0.0075** (0.75%)
- `atr_window` : **20**
- `atr_stop_multiple` : **2.5**
- `max_positions` : **10**
- `max_position_weight` : **0.10** (10%)
- `max_sector_weight` : **0.225** (22.5%)
- `max_gross_exposure` : **1.0**
- `min_position_notional` : **1_000.0**

### Pourquoi ce réglage

- `0.75%` par trade est plus prudent que `1%`, ce qui convient bien à un moteur initial de production ;
- `10` positions donnent un portefeuille assez concentré sans tomber dans l’excès ;
- `22.5%` par secteur évite les poches sectorielles trop lourdes ;
- `2.5 ATR` est un compromis raisonnable pour du swing daily.

---

## 5.3 Paramètres circuit breaker

### Paramètres recommandés

- `max_portfolio_drawdown_pct` : **0.12** (12%)
- `max_daily_loss_pct` : **0.025** (2.5%)

### Pourquoi

- 15% de drawdown max est encore assez large pour un portefeuille cash daily ;
- 12% force une discipline plus professionnelle ;
- 5% de perte journalière max est trop haute pour un portefeuille cash swing discipliné ;
- 2.5% est plus cohérent avec un moteur conservateur.

---

## 5.4 Paramètres corrélation

### Paramètres recommandés

- `correlation_threshold` : **0.80**
- `correlation_lookback_days` : **126**
- `correlation_min_overlap` : **90**

### Pourquoi

- 126 séances donne environ 6 mois de bourse, plus stable que 60 ;
- 90 séances de recouvrement rendent le signal pairwise plus crédible ;
- 0.80 reste un seuil simple, lisible, et déjà proche du réglage actuel.

---

## 5.5 Paramètres Kelly

### Recommandation cible

- `enable_kelly_sizing` : **False** par défaut
- `assumed_payoff_ratio` : **1.5** si mode expérimental activé
- `kelly_fraction_multiplier` : **0.10 à 0.20** si activé
- `min_effective_probability` : **0.55** minimum si activé
- `default_win_rate` : **à éviter comme béquille de production**

### Décision recommandée

Pour ton cas d’usage, je recommande :

- **Kelly OFF** en production standard ;
- Kelly uniquement pour une branche d’expérimentation contrôlée ;
- jamais comme sizing par défaut tant que le pipeline ML n’est pas entièrement PIT-safe et calibré.

---

## 5.6 Politique de fallback recommandée

### Cible métier

- prix invalide = rejet
- ATR absent = rejet
- métrique ML absente = pas de Kelly, mais moteur ATR possible
- snapshot compte absent = blocage du run live
- matrice de corrélation absente = mode dégradé documenté, mais log explicite

### Pourquoi

En production risque, il vaut mieux un **rejet explicite** qu’un sizing de secours mal maîtrisé.
