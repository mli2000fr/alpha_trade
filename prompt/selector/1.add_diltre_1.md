# 1.add_diltre_1 — Synthèse des améliorations selector swing

## Objectif

Cette vague de travail avait deux buts :

1. rendre le mode **strict swing cash** systématique dans le scanner final ;
2. compléter les critères swing qui restaient bloqués faute de données :
   - `market_cap`
   - `beta_126`
   - `spread_bps`
   - `earnings_blackout`

---

## Ce qui a été mis en place

### 1. Le mode strict est désormais implicite

Le lancement standard :

```powershell
python -m selector.alpha_scanner
```

charge maintenant automatiquement `STRICT_SWING_CASH_FILTERS`.

L'ancien argument `--preset strict` reste toléré comme alias de compatibilité, mais il n'est plus nécessaire.

Conséquence :

- la CLI standard applique directement les filtres swing stricts ;
- l'IHM ne propose plus de logique optionnelle distincte ;
- le backfill PIT utilise le même profil strict par défaut.

---

### 2. Les 4 critères swing manquants sont câblés end-to-end

#### `market_cap`

- source principale : `stock_metadata.market_cap`
- alimentée en amont via Finnhub
- utilisée dans `AlphaScanner.apply_filters()`
- persistée dans `stock_scores` et `stock_scores_history`

#### `beta_126`

- calcul local à partir des rendements journaliers du titre vs `SPY`
- fenêtre : jusqu'à `126` séances
- utilisée dans `apply_filters()`
- persistée dans `stock_scores` et `stock_scores_history`

#### `spread_bps`

- source : `stock_quote_snapshots`
- récupérée depuis les latest quotes Alpaca
- fusionnée dans le scanner via overlay par symbole
- utilisée dans `apply_filters()`
- persistée dans `stock_scores` et `stock_scores_history`

#### `earnings_blackout`

- source : `stock_earnings_calendar`
- calcule `earnings_date`, `days_to_earnings` et `earnings_blackout`
- supporte un `reference_date` pour cohérence live / point-in-time
- utilisée dans `apply_filters()`
- persistée dans `stock_scores` et `stock_scores_history`

---

## Seuils stricts actuellement appliqués

Le profil partagé `STRICT_SWING_CASH_FILTERS` applique désormais :

- `min_close = 10`
- `avg_dollar_volume_20d >= 30_000_000`
- `max_volatility_ratio <= 0.90`
- `relative_strength_index >= 100`
- `close > MA200`
- `close / high_52w >= 0.75`
- `weekly_trend_score >= 1.0`
- `1.5 % <= atr_pct_20 <= 6 %`
- `market_cap >= 2_000_000_000`
- `beta_126 >= 1.0`
- `spread_bps <= 25`
- exclusion si `earnings_date` tombe dans les `3` prochains jours

---

## Cohérence live / backfill / IHM

### CLI

- `python -m selector.alpha_scanner` => strict implicite

### IHM

- l'étape `Alpha Scanner` lance maintenant directement `python -m selector.alpha_scanner`
- il n'y a plus de case « activer le preset strict »

### Backfill PIT

- `BackfillScoresHistoryService` utilise `AlphaScannerConfig.strict_swing_cash()` par défaut
- les overlays quotes / earnings sont relus avec `reference_date=as_of_date`
- cela évite un biais temporel sur `spread_bps` et `days_to_earnings`

---

## Schéma / persistance

Les colonnes selector enrichies sont maintenant prévues dans :

- `stock_scores`
- `stock_scores_history`

Colonnes concernées :

- `market_cap`
- `beta_126`
- `spread_bps`
- `earnings_date`
- `days_to_earnings`
- `earnings_blackout`

Tables de référence ajoutées / utilisées :

- `stock_quote_snapshots`
- `stock_earnings_calendar`

---

## Impact métier

Avec ces changements, le scanner final est beaucoup plus proche d'une checklist swing « pro » :

- meilleure exécutabilité réelle grâce au filtre de spread ;
- réduction du risque microcap / manipulation avec la market cap ;
- focus sur des titres plus directionnels avec `beta_126` ;
- suppression des paris binaires juste avant résultats grâce au blackout earnings ;
- cohérence des critères entre live, IHM, backfill PIT et backtest.

---

## Remarque

Les facteurs calculés en mémoire (`atr_pct_20`, `weekly_trend_score`, `high_52w_proximity`, etc.) restent utilisés dans la décision du scanner, même quand ils ne sont pas tous persistés individuellement dans les tables historiques. Les nouveaux champs bloquants demandés, eux, sont bien persistés explicitement.
