# Screener — Évolution phase 3 orientée résultat trading

## Objectif

Après :
- la phase 1 (garde-fous + normalisation),
- la phase 2 (2 passes + performance + métriques),

la phase 3 vise la **qualité des candidats de trading** pour un usage **swing cash daily US**.

L’idée n’est plus seulement de faire tourner le `screener` plus vite, mais de livrer au `selector` un univers déjà plus pertinent :
- plus liquide,
- plus fort relativement,
- plus proche de ses highs récents,
- plus cohérent avec une logique de momentum / leadership.

---

## Ce que j’ai modifié

### 1. Recalibrage du `ScreenerConfig` pour le swing cash
Fichier : `screener/models.py`

J’ai fait évoluer les paramètres par défaut vers un profil davantage orienté trading réel :

- `liquidity_threshold_usd = 10_000_000.0`
- `historical_range_lookback_days = 504`
- `min_relative_strength_index = 100.0`
- `min_historical_range_score = 70.0`
- poids recalibrés :
  - `weight_liquidity = 0.15`
  - `weight_relative_strength = 0.55`
  - `weight_historical_range = 0.30`

### Pourquoi
- `500k$` de liquidité moyenne quotidienne était trop faible pour un filtre initial sérieux sur actions US swing ;
- un range sur 10 ans est souvent trop lointain pour un usage swing ;
- la force relative doit dominer davantage le préfiltrage ;
- être trop loin des highs récents est rarement optimal pour une logique de leadership momentum.

### Effet
Le `screener` devient plus cohérent avec un pipeline qui cherche :
- des titres tradables proprement,
- déjà en leadership relatif,
- encore bien positionnés dans leur structure de prix récente.

---

### 2. Filtre précoce sur la force relative
Fichier : `screener/pipeline.py`

Dans `screen_recent_prices(...)`, après le calcul de `relative_strength_index`, j’ai ajouté un filtre direct :

- exclusion des symboles avec `relative_strength_index < min_relative_strength_index`

### Pourquoi
Pour du swing cash, il est souvent rentable de sortir très tôt :
- les retardataires,
- les titres qui sous-performent le benchmark,
- les noms qui survivraient sinon juste grâce à leur liquidité.

### Effet
La passe 2 historique n’est déclenchée que pour des symboles déjà crédibles du point de vue du momentum relatif.

---

### 3. Range historique recentré sur une fenêtre trading utile
Fichier : `screener/pipeline.py`

Le calcul du range historique ne porte plus implicitement sur toute la profondeur disponible utile au chargement.

Il est maintenant borné par :
- `historical_range_lookback_days`

Donc le score :
- `historical_range_score`

mesure désormais la position du titre dans un **range récent exploitable**, par défaut sur environ **2 ans de bourse** (`504` jours calendaires glissants dans l’implémentation actuelle).

### Pourquoi
Pour du swing trading :
- la proximité des highs récents est plus utile que la proximité d’un high vieux de 6 ou 10 ans ;
- les vieux extrêmes historiques peuvent diluer artificiellement l’information utile.

### Effet
Le score de range devient plus discriminant pour identifier des leaders proches de leurs zones de force récente.

---

### 4. Filtre explicite sur la proximité des highs récents
Fichier : `screener/pipeline.py`

Après calcul du `historical_range_score`, j’exclus désormais les symboles sous :
- `min_historical_range_score`

Par défaut :
- `70.0`

### Pourquoi
Un titre :
- très loin de ses highs récents,
- même s’il est liquide,
- même s’il a un historique suffisant,

n’est souvent pas un bon candidat de préfiltrage pour une logique swing momentum/cash.

### Effet
Le `screener` retient davantage des titres déjà bien placés structurellement.

---

### 5. Loader SQL historique aligné avec la logique trading
Fichier : `screener/db_io.py`

Le loader SQL des agrégats historiques :
- `load_historical_range_stats_for_symbols(...)`

utilise désormais lui aussi :
- `historical_range_lookback_days`

au lieu de s’appuyer sur la profondeur historique longue.

### Pourquoi
Il fallait aligner :
- la logique métier du score,
- la logique de chargement SQL,
- la logique de performance de la phase 2.

### Effet
La réduction de coût reste intacte, mais avec une fenêtre historiquement plus pertinente pour le swing.

---

### 6. CLI enrichie pour piloter la qualité des candidats
Fichier : `screener/stock_screener.py`

J’ai ajouté des options CLI pour piloter directement les nouveaux leviers :

- `--liquidity-threshold-usd`
- `--min-relative-strength-index`
- `--historical-range-lookback-days`
- `--min-historical-range-score`

### Pourquoi
Tu peux maintenant ajuster rapidement le comportement du `screener` selon :
- le régime de marché,
- le degré de sélectivité souhaité,
- la taille de l’univers,
- la philosophie de sélection voulue avant le `selector`.

## Impact trading attendu

### Avant la phase 3
Le `screener` était surtout :
- propre,
- plus performant,
- mieux instrumenté,

mais restait encore relativement permissif sur la **qualité directionnelle** des candidats.

### Après la phase 3
Le `screener` favorise davantage :
- les titres liquides ;
- les titres qui battent déjà le benchmark ;
- les titres proches de leurs highs récents ;
- les titres plus compatibles avec un workflow de swing momentum cash.

### En pratique
Cela doit réduire :
- le bruit transmis au `selector` ;
- le nombre de titres “survivants techniques mais peu tradables mentalement / structurellement” ;
- les cas où le `selector` passe son temps à éliminer des symboles qui n’auraient jamais dû passer le `screener`.

---

## Ce que je n’ai volontairement pas déplacé dans le `screener`

Je n’ai **pas** dupliqué dans le `screener` les signaux avancés déjà mieux placés dans `selector` :
- `trend_score`
- `vcp_score`
- `ATR`
- `weekly_trend_score`
- neutralisation sectorielle avancée

### Pourquoi
Le bon découpage reste :
- `screener` = préfiltrage robuste, rapide, orienté exploitabilité ;
- `selector` = sophistication du ranking final.

## Pourquoi cette phase 3 est orientée résultat trading

Parce qu’elle améliore directement la **qualité de l’univers envoyé au `selector`**.

Le gain espéré n’est pas seulement technique :
- moins de retardataires,
- moins de titres “loin de leur zone de force”,
- plus de leaders relatifs,
- plus de cohérence avec une logique swing cash exploitable.

En d’autres termes :
- phase 1 = screener plus propre,
- phase 2 = screener plus rapide,
- phase 3 = screener plus **utile pour trader**.

## Recommandation logique pour la suite

La meilleure phase 4 probable serait de mesurer l’impact réel en backtest / walk-forward sur :
- hit rate,
- average gain / loss,
- drawdown,
- turnover,
- ratio de survie `screener -> selector -> portefeuille cible`

Et de comparer plusieurs jeux de paramètres :
- `RS min = 100 / 102 / 105`
- `range lookback = 252 / 504 / 756`
- `min_historical_range_score = 65 / 70 / 75`
- `liquidity_threshold_usd = 5M / 10M / 20M`

C’est là que tu transformeras cette phase 3 en avantage trading objectivé.
