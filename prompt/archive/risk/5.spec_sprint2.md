## 3.2 Utilisation effective de ces champs dans les ordres enfants

### `execution_engine/order_intents.py`

Les ordres enfants exploitent maintenant les champs de risque de la cible lorsqu’ils sont présents.

#### Take profit

`build_take_profit_intent(...)` accepte maintenant une cible `ExecutionTarget` optionnelle.

Règle appliquée :
- base historique conservée : cible en `%` via `profit_taker_pct` ;
- si `risk_per_share` est disponible, calcul d’une cible **risk-based** à **2R** ;
- la limite finale prend la valeur la plus protectrice / ambitieuse entre la règle `%` et la règle `2R`.

#### Trailing stop

`build_trailing_stop_intent(...)` accepte aussi la cible enrichie.

Règle appliquée :
- si `stop_price_initial` est disponible, le `trail_percent` est dérivé de la distance entre le prix de fill et ce stop initial ;
- sinon, fallback sur `risk_per_share / fill_price` ;
- sinon, fallback sur la config historique `trailing_stop_pct`.

### Effet métier

Le moteur d’exécution utilise maintenant **réellement** le risque décidé amont pour construire ses protections aval.
Ce n’est plus seulement de la traçabilité.
