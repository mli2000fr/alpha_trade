# Centralisation des seuils stricts dans une configuration unique

## Objectif

Éviter toute duplication des seuils stricts entre :

- `selector/alpha_scanner.py`
- `prompt/fix_swing/run_strict_oos_2025q1.py`
- `prompt/fix_swing/run_filtered_case_real.py`

Les seuils concernés sont :

- `min_close = 10.0`
- `min_avg_dollar_volume_20d = 30_000_000.0`
- `max_volatility_ratio = 0.9`

---

## Solution mise en place

### 1) Nouvelle source unique : `selector/strict_filter_profiles.py`

Un nouveau module partagé a été créé :

- `selector/strict_filter_profiles.py`

Il contient :

### `StrictFilterProfile`
Une dataclass dédiée qui encapsule les seuils stricts métier.

### `STRICT_SWING_CASH_FILTERS`
Le preset unique centralisé pour le cas d’usage :

- petit compte
- mode cash
- swing strict

Ce profil expose deux conversions utiles :

- `to_backtest_filter_dict()`
  - pour les scripts de rerun/backtest
- `to_scanner_config_kwargs()`
  - pour `AlphaScannerConfig`

et un helper :

- `apply_to_frame(...)`
  - pour appliquer les seuils PIT sur un DataFrame sans recopier les conditions partout

---

## 2) Changements dans `selector/alpha_scanner.py`

Le scanner consomme désormais ce profil partagé.

### Ajouts réalisés
- import de `STRICT_SWING_CASH_FILTERS`
- import de `StrictFilterProfile`
- ajout de `AlphaScannerConfig.from_filter_profile(...)`
- ajout de `AlphaScannerConfig.strict_swing_cash(...)`

### Bénéfice
Au lieu de recopier les valeurs strictes dans plusieurs scripts, on peut maintenant construire un scanner strict via :

```python
AlphaScannerConfig.strict_swing_cash(...)
```

Donc :
- une seule source de vérité pour les seuils
- moins de risque d’écart entre backfill, scanner et rerun

---

## 3) Changements dans `prompt/fix_swing/run_strict_oos_2025q1.py`

Avant :
- une constante locale `STRICT_FILTERS` contenait les mêmes seuils recopiés à la main
- `AlphaScannerConfig(...)` recevait ces valeurs une par une

Maintenant :
- `STRICT_FILTERS = STRICT_SWING_CASH_FILTERS.to_backtest_filter_dict()`
- le backfill utilise :

```python
AlphaScannerConfig.strict_swing_cash(...)
```

### Bénéfice
Le backfill strict reconstruit `stock_scores_history` avec exactement le même preset centralisé que le rerun filtré.

---

## 4) Changements dans `prompt/fix_swing/run_filtered_case_real.py`

Avant :
- une constante locale `FILTERS` dupliquait les mêmes seuils
- le masque PIT était écrit en dur avec 3 conditions répétées

Maintenant :
- `FILTERS` provient du profil partagé via `to_backtest_filter_dict()`
- l’application réelle du filtre se fait via :

```python
STRICT_SWING_CASH_FILTERS.apply_to_frame(filtered_scores)
```

### Bénéfice
Le rerun OOS et le backtest PIT utilisent la même définition stricte, sans redondance de logique ni de valeurs.

---

## 5) Pourquoi cet emplacement est le bon

Le bon endroit pour centraliser est **`selector/strict_filter_profiles.py`** parce que :

1. le filtre appartient au domaine de **sélection des titres** ;
2. il doit rester importable à la fois depuis le scanner et depuis les scripts `prompt/fix_swing/` ;
3. cela évite de dépendre d’un script de backtest depuis le code métier ;
4. cela garde `AlphaScanner` cohérent avec les reruns PIT et les backfills.

En pratique :
- le **scanner** consomme le profil ;
- le **backfill strict** consomme le même profil ;
- le **rerun PIT backtest** consomme aussi le même profil.
