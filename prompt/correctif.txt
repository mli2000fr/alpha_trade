🏦 Audit Quantitatif — Alpha Trade
Standard Two Sigma / Citadel · 審查報告
Verdict global : Maturité intermédiaire-avancée. Architecture modulaire propre, FinBERT intégré, concurrence gérée, dataclasses frozen. Mais des lacunes critiques empêchent une mise en production : absence totale de Risk Management, look-ahead bias dans les facteurs, adj_close non ajusté, et absence de CI/CD.

1. 🏗️ Architecture Design
✅ Points forts
Séparation claire des couches : screener / selector / event_sentiment / dataIntegrityEngine
AlphaScannerConfig en frozen=True dataclass avec __post_init__ validation
Injection de l'engine SQLAlchemy dans AlphaScanner.__init__
❌ Problèmes critiques
Sévérité	Problème	Correction
P0	common/utils.py : US_MARKET_HOLIDAYS hardcodé avec seulement 4 jours fixes — MLK, Presidents' Day, Good Friday, Memorial Day, Labor Day, Thanksgiving manquants	Remplacer par pandas_market_calendars (déjà dans requirements.txt mais jamais utilisé) et partager trading_calendar.py depuis event_sentiment/ vers common/
P1	DataSanitizer et _process_chunk du screener appellent get_sqlalchemy_engine() directement dans les workers — couplage fort, anti-pattern dans un contexte multi-process	Standardiser : tous les composants reçoivent un Engine en paramètre
P1	DataSanitizer._reflect_tables() appelé dans __init__ : introspection DDL à chaque instanciation → overhead	Déclarer les Table en statique dans database/ et les importer
P2	Aucun Protocol / ABC pour DataFetcher, ScoringEngine, RiskChecker → mocking difficile, remplacement risqué	Définir des Protocol dans un module core/interfaces.py
2. 🗄️ Data Layer
✅ Points forts
pool_pre_ping=True, pool_recycle=3600
Upsert en batch (chunksize=1000)
Polars pour les transformations lourdes dans le sanitizer
❌ Problèmes critiques
Sévérité	Problème	Correction
P0	adj_close non ajusté : adj_close est une simple copie de close. Aucun ajustement splits/dividendes → tous les rendements historiques sont biaisés	Utiliser l'endpoint Alpaca qui fournit un adj_close pré-ajusté, ou appliquer un facteur cumulatif
P0	Look-ahead bias (backtest) : historical_range_score dans screener/pipeline.py calcule hist_high/hist_low sur tout l'historique y compris les données post-date-de-référence	Borner explicitement à timestamp <= as_of_date
P1	Pas de pool_size explicite : avec ProcessPoolExecutor, chaque processus crée son propre engine → N workers × 5 connexions par défaut	Ajouter pool_size=2, max_overflow=3 + documenter le modèle multi-process
P1	Pas de versioning des données : impossible de distinguer les versions après re-ingestion	Ajouter colonnes ingested_at TIMESTAMP, source_version VARCHAR dans stock_bars_daily
3. 📊 Factor Engineering & Signal Generation
✅ Points forts
7 critères Minervini implémentés dans trend_score
VCP score basé sur ratio de volatilité (contraction de range)
Neutralisation sectorielle avec plafond round-robin
❌ Problèmes critiques
Sévérité	Problème	Correction
P0	Facteurs non-neutralisés cross-section : RSI et historical_range_score non neutralisés par secteur → les titres dans un secteur en bull systématique dominent	Calculer des z-scores cross-sectionnels par secteur avant composition
P1	Winsorisation absente : _normalize_zero_one() utilise min-max pur → 1 outlier suffit à comprimer tous les scores vers 0	Winsoriser au 1e–99e percentile avant normalisation, ou utiliser un ranking percentile
P1	Poids hardcodés sans validation IC : final_score = 0.5*(trend+vcp) + 0.3*total_score + 0.2*rsi — arbitraire	Calculer l'IC rolling (corrélation rang facteur → rendement futur 5/10/20j) et utiliser l'IC-weighted combination
P1	vcp_score non validé empiriquement : pondéré à 50% sans backtest de corrélation	Valider via backtest avant de lui accorder ce poids
4. ⚠️ Risk Management — MODULE ABSENT (Gap critique P0)
Aucun module de gestion du risque n'existe dans le projet. Pour un système Swing Trade, c'est le gap le plus dangereux en production.

Ce qui manque absolument
Composant	Description
risk/position_sizer.py	ATR-based sizing, Kelly criterion (½-Kelly fraction)
risk/portfolio_risk.py	VaR paramétrique + historique, CVaR, matrice de corrélation
risk/drawdown_guard.py	Circuit-breaker si drawdown portefeuille > seuil configurable
Corrélation inter-positions	La neutralisation sectorielle (30% cap) est une proxy grossière
risk/
├── __init__.py
├── position_sizer.py     # ATR stop, Kelly sizing
├── portfolio_risk.py     # VaR, CVaR, correlation matrix
├── drawdown_guard.py     # Circuit-breaker
└── models.py             # RiskReport dataclass
