## 2. Branchement explicite du walk-forward dans `backtesting run`

### Fichier modifié
- `backtesting/cli.py`

### Nouvelles options ajoutées à la commande `run`
- `--score-column`
  - valeurs : `auto`, `final_score_walk_forward`, `final_score_sentiment`, `final_score`
  - défaut : `auto`
- `--walk-forward-artifacts-dir`
  - chemin racine explicite où chercher les meilleurs poids walk-forward à appliquer au backtest standard

### Comportement obtenu
Dans `backtesting run` :
1. les scores sont toujours chargés via `load_scores()`
2. `prepare_scores_for_sentiment_mode()` peut désormais recevoir un répertoire explicite d’artefacts walk-forward
3. `replay_signals()` reçoit explicitement la colonne de score demandée si `--score-column` n’est pas `auto`
4. les paramètres utilisés sont ajoutés au rapport JSON structuré

### Effet recherché
Le mode standard `run` peut désormais :
- rester en mode legacy (`auto`)
- ou être piloté explicitement pour consommer un scoring walk-forward si l’utilisateur le souhaite
