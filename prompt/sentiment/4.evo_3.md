# Sprint 3 — propagation idiosyncratique / macro et poids walk-forward

## Objectif
Propager de manière additive et rétrocompatible :
- la séparation `company_idio` / `macro_regime`
- les poids réellement utilisés en walk-forward
- la source de score effectivement consommée (`final_score_walk_forward` → `final_score_sentiment` → `final_score`)

## Changements principaux

### 1. Contrat score enrichi
Ajout de champs transportés dans le flux score → portefeuille :
- `score_source`
- `company_idio_score`
- `macro_regime_score`
- `company_idio_signal_norm`
- `macro_regime_signal_norm`
- `company_idio_component`
- `macro_regime_component`
- `quant_component`
- `walk_forward_sentiment_weight`
- `walk_forward_macro_weight`
- `walk_forward_quant_weight`
- `calibration_run_id`
- `calibration_source`

Fichiers touchés :
- `risk_management/models.py`
- `risk_management/portfolio_builder.py`
- `risk_management/db_io.py`
- `risk_management/audit.py`

### 2. Walk-forward utilitaire
Création de `backtesting/walk_forward.py` pour :
- découvrir automatiquement les artefacts de poids :
  - `latest_best_weights.json`
  - `walk_forward_best_weights_latest.json`
  - `champion_weights.json`
- reconstituer `final_score_walk_forward`
- renseigner les poids et métadonnées de calibration sur les DataFrames de scores

### 3. Backtesting : fallback et overlay automatique
Mise à jour de :
- `backtesting/data_loader.py`
- `backtesting/resilience.py`
- `backtesting/signal_replay.py`
- `backtesting/cli.py`

Comportement visé :
1. charger les colonnes walk-forward si elles existent
2. si un artefact walk-forward récent est trouvé, recalculer `final_score_walk_forward`
3. tracer `score_source` sur chaque ligne
4. rejouer les signaux avec priorité :
   - `final_score_walk_forward`
   - `final_score_sentiment`
   - `final_score`

### 4. Séparation idio / macro dans l’agrégateur
Mise à jour de `event_sentiment/signal_aggregator.py` pour :
- exposer explicitement `company_idio_score` et `macro_regime_score`
- préparer la persistance de `final_score_walk_forward` et des poids/calibration
- rester compatible avec le calcul historique de `final_score_sentiment`

### 5. Historisation PIT
Mise à jour de :
- `backtesting/backfill_scores_history.py`
- `screener/db_io.py`

But : archiver un snapshot PIT plus complet dans `stock_scores_history`, incluant :

- métadonnées de calibration
