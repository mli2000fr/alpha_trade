# Correctif conservateur du trailing stop — impact réel sur les backtests

## Ce que j’ai corrigé

J’ai rendu la logique de trailing stop **plus conservatrice** dans `backtesting/simulator.py`.

### Avant
Le moteur :
- utilisait le `high` du jour pour remonter `peak_high`
- recalculait le trailing stop avec ce nouveau plus haut
- pouvait ensuite déclencher ce stop sur **la même bougie**

C’était optimiste.

### Maintenant
Le moteur :
- calcule le trailing stop du jour avec le **peak précédent**
- décide la sortie
- **puis seulement** met à jour `peak_high` avec le `high` du jour si la position reste ouverte

Donc on supprime le biais :
> “le stop connaît déjà le high du jour avant d’être touché”.

J’ai aussi ajouté un test de non-régression pour ça.

# Pourquoi il reste quand même des trailing au-dessus du TP ?

Tu pourrais te dire :
> “si on a corrigé, pourquoi il reste encore 20 trailing exits au-dessus du TP ?”

### Réponse
Cette fois, ce n’est pas forcément un bug.

Si une position reste ouverte **plusieurs jours**, le `peak_high` des jours précédents peut légitimement remonter le trailing stop au-dessus du niveau du TP initial.

Exemple :
- entrée à 100
- TP initial = 108
- le trade monte à 120 sur les jours suivants
- le trailing stop peut ensuite être à 114
- sortir à 114 est normal

Donc :
- **avant** : une partie de ces sorties venait du biais sur la même barre
- **après** : celles qui restent sont souvent plausibles, car elles viennent de peaks antérieurs

# Ce qui reste à surveiller

## 1) Concentration très forte du PnL
Le swing reste dominé par quelques tickers très explosifs.

- `BNAI`
- `TRON`

Donc la perf reste :

---

## 2) Sizing encore potentiellement optimiste
Le moteur valorise les positions ouvertes avec le `close` du jour pour calculer l’equity dans la boucle quotidienne.

Ce n’est pas le gros biais principal, mais ça peut encore :
- améliorer un peu artificiellement la taille des nouvelles positions
- surtout sur des journées très directionnelles

---

## 3) Daily OHLC reste une approximation
Même avec la correction :
- on ne connaît pas l’ordre exact intraday
- on prend une convention conservatrice, mais toujours simplifiée

Pour être encore plus robuste, il faudrait :
- soit une convention encore plus pessimiste sur certains cas ambigus
- soit des données intraday
