## 2. Modifications code

### 2.1 `modelFactory/drift_policy.py` *(nouveau, A-021)*

- Dataclass `MLPolicyDecision(model_id, drift_status, gate, action, reason, ks_pvalue, psi, n_samples, n_baseline, computed_at)`.
- `evaluate_drift_gate(report, *, kill_on=("ALERT",), warn_grace=True)` :
  - `status == "ALERT"` → `gate="disabled"`, `action="kill_switch_ml"` ;
  - `status == "WARN"` → `enabled` (grâce par défaut) + log WARNING ;
  - `status == "OK"` ou rapport absent → `enabled / allow` ;
  - `notes` contient `sample_size_too_small` → `allow` (pas une dérive).
- `apply_kill_switch(decision, df)` : annote `ml_disabled` et neutralise
  `predicted_proba` / `raw_proba` quand le kill switch est actif.
- `persist_kill_switch_event(decision, *, engine)` : insert dans
  `ml_drift_runs` avec `payload.gate_action="kill_switch_ml"` (rétro-compat,
  pas de nouvelle table).
- `summary_fields(decision)` : factorise les 5 champs injectés dans
  `run_summary` ML.

### 2.2 `modelFactory/cli.py` *(modifié, A-021)*

- Mode `predict` : après `predict_batch(...)`, appel `compute_drift` ↔
  `evaluate_drift_gate` ↔ `apply_kill_switch` ↔ `persist_kill_switch_event`.
- Helper privé `_load_drift_baseline(engine, days=30)` (lecture rolling
  `model_predictions`, best-effort, fail-safe).
- `_build_run_summary(..., drift_decision=None)` : nouveaux champs
  exposés via `summary_fields(...)` :
  - `ml_drift_status` (`OK|WARN|ALERT|n/a`)
  - `ml_kill_switch_active` (bool)
  - `ml_kill_switch_reason` (str | null)
  - `ml_drift_ks_pvalue` (float | null)
  - `ml_drift_psi` (float | null)
- `update_runtime_status(ml_drift_status=..., ml_kill_switch_active=...)` →
  remontée IHM via heartbeats.

> **Scope choisi** : exposition + persistance en S4. La consommation côté
> `risk_management` (refus de lire `model_predictions` si flag actif) sera
> traitée Sprint S8 conformément au plan (« Drift gate auto »).
