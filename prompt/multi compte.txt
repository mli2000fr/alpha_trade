🏦 Comment configurer et utiliser le multi-comptes
1. Configurer les comptes
Option A — config.yaml (recommandé) :
alpaca:
  accounts:
    - id: default
      label: "Paper principal"
      api_key: "${ALPACA_API_KEY}"
      secret_key: "${ALPACA_SECRET_KEY}"
      mode: paper
    - id: live1
      label: "Compte live"
      api_key: "${ALPACA_LIVE1_API_KEY}"
      secret_key: "${ALPACA_LIVE1_SECRET_KEY}"
      mode: live
Les ${VAR} sont résolus depuis les variables d'environnement.

Option B — Variables d'env uniquement :
# Compte par défaut
$env:ALPACA_API_KEY = "PK..."
$env:ALPACA_SECRET_KEY = "..."

# Compte supplémentaire (ID = live1)
$env:ALPACA_LIVE1_API_KEY = "AK..."
$env:ALPACA_LIVE1_SECRET_KEY = "..."
$env:ALPACA_LIVE1_MODE = "live"

2. Lancer les modules avec un compte spécifique
# Risk management
python -m risk_management.run_risk --account-equity 100000 --account live1

# Exécution
python run_execution.py paper --account default    # compte paper
python run_execution.py live --account live1        # compte live

# Corporate actions
python -m corporate_actions sync --account live1
python -m corporate_actions apply --account live1

# Menu interactif (sélection du compte proposée si >1 compte)
python run_execution.py

Sans --account, le premier compte configuré est utilisé (rétrocompatibilité totale).

3. Distinguer les comptes dans l'IHM
Quand plusieurs comptes sont détectés, un sélecteur « 🏦 Compte Alpaca » apparaît dans la sidebar
Les pages Execution et Positions broker filtrent automatiquement par le compte sélectionné
Les pages Screening, Risk et Corporate Actions affichent les données globales (les CA events sont partagés, les risk decisions sont filtrées par run_id)

4. Migration DB
Pour les bases existantes, exécuter la migration :
# Via Alembic
alembic upgrade head

# Ou manuellement
mysql -u user -p alpha_trade < database/sql/migration_add_account_id.sql

Cela ajoute account_id VARCHAR(32) DEFAULT 'default' à 6 tables et migre les données existantes vers 'default'.
