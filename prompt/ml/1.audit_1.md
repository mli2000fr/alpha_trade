# Audit 1 — modelFactory

## Ce que j’ai modifié

### 1. Robustesse corporate actions dans `modelFactory/features.py`
J’ai corrigé un point très important pour des historiques actions sur 10 ans :

- les features prix et la target utilisent maintenant les **prix ajustés** quand `adj_close` est disponible ;
- le code reconstruit un OHLC/VWAP ajusté via le ratio `adj_close / close` ;
- `daily_return` est recalculé depuis la série ajustée.

### Pourquoi c’est critique
Avec des splits/dividendes, un modèle entraîné sur `close` brut peut apprendre de faux crashs / faux gaps.
Pour du swing daily, c’est un biais majeur.

---

### 2. Métriques de test séparées dans `modelFactory/model.py`
Avant :
- `test_step()` réutilisait `val_acc`.

Maintenant :
- métriques de test dédiées : `test_acc`, `test_precision`, `test_recall`, `test_auc`.

### Pourquoi c’est important
Sinon tu pollues l’état des métriques entre validation et test, et tes chiffres deviennent moins fiables.

---

### 3. Évaluation sur le **meilleur checkpoint** dans `modelFactory/trainer.py`
Avant :
- le test était lancé sur le **dernier état entraîné**, pas forcément le meilleur ;
- les métriques `val_*` récupérées correspondaient plutôt à la fin du run qu’au meilleur modèle.

Maintenant :
- validation et test sont exécutés avec `ckpt_path="best"`;
- les métriques persistées reflètent le **meilleur checkpoint** ;
- `best_epoch` est extrait du checkpoint et persisté proprement.

### Pourquoi c’est important
En prod, ce qui compte, c’est le modèle que tu sauvegardes et réutilises, pas le dernier batch de l’epoch finale.

---

J’ai ajouté des tests utiles sur :
- l’usage de `adj_close` dans la target ;
- l’absorption correcte d’un split dans les features ;
- la séparation des métriques de test ;
- l’extraction de `best_epoch`.

# Les limites majeures actuelles

## 1. Un LSTM par symbole : probablement trop coûteux / pas optimal
Avec ~10 ans de daily :
- ~2520 barres
- après warm-up et horizon : ~2400 obs utiles
- après split train/val/test : train effectif souvent ~1600-1700 points

Pour un modèle `LSTM(hidden=128, layers=2)` **par symbole**, c’est peu.
Le ratio signal/bruit est faible, et le risque est :

- surapprentissage
- instabilité d’un run à l’autre
- généralisation médiocre par régime
- maintenance lourde si tu as beaucoup de tickers

### Recommandation
À moyen terme :
- comparer systématiquement à un **modèle global cross-sectional**
- par ex. :
  - `LightGBM` / `CatBoost` en baseline forte
  - ou modèle séquentiel global avec `symbol embedding`

### En pratique
Pour du swing daily, un bon **GBDT tabulaire** bat très souvent un LSTM par symbole.

---

## 2. La target actuelle est trop naïve pour du swing cash
Aujourd’hui :
- `target = 1 si return future à horizon > 0`

C’est trop brut pour ton usage.

### Problème
En swing cash, tu ne veux pas seulement savoir si ça monte un peu.
Tu veux savoir si le move est **suffisant** pour justifier :

- risque pris
- coût implicite
- temps immobilisé
- bruit de marché

### Recommandation
Passer à une target type :

- `1 si future_return_h > threshold`
- avec threshold fixe ou mieux :
  - lié à l’ATR
  - ou aux coûts + buffer
  - ou à une logique “tradeable move”

Exemples :
- `future_5d_return > 1.0%`
- ou `future_5d_return > 0.5 * ATR_20_norm`
- ou target à 3 classes :
  - short/avoid
  - no-trade
  - long

### Pour du cash swing
Le plus pertinent est souvent :
- **long / no-trade**
plutôt que
- hausse / baisse

---

## 3. Tes probabilités ne sont pas calibrées
`risk_management` consomme `predicted_proba`.
Donc la calibration est essentielle.

Aujourd’hui :
- tu sors un `softmax`
- tu le traites comme une probabilité exploitable

Mais un score softmax non calibré peut être très trompeur :
- 0.72 n’est pas forcément un vrai 72%
- deux modèles peuvent avoir même AUC mais calibration très différente

### Recommandation prioritaire
Ajouter :
- calibration `Platt` ou `Isotonic`
- métriques :
  - `Brier score`
  - `ECE` (Expected Calibration Error)
  - reliability bins

Et persister :
- `calibrated_proba`
- `decision_threshold`
- métriques de calibration

### Pourquoi c’est très important
Si ton sizing dépend de la conviction, la calibration vaut parfois plus que 2 points d’accuracy.

---

## 4. Validation trop simple pour une série financière
Actuellement :
- un seul split chrono train/val/test

C’est propre, mais insuffisant pour valider sérieusement une stratégie.

### Risques
- dépendance à un seul régime de marché
- faux positif sur une période favorable
- hyperparamètres optimisés implicitement sur une seule coupe

### Recommandation
Passer à une validation :
- **walk-forward**
- **rolling / expanding window**
- avec éventuellement **purge + embargo**

Pour de la finance, c’est le standard minimum sérieux.

---

## 5. Les séquences val/test perdent du contexte aux frontières
Dans `dataset.py` :
- tu fais d’abord le split
- puis tu construis les séquences dans chaque split

Conséquence :
- le début de `val` et `test` ne peut pas utiliser les `sequence_length` derniers jours du split précédent
- tu perds de l’information utile
- tu réduis le nombre d’exemples évaluables

### Recommandation
Construire les séquences avec :
- scaler fit sur train uniquement
- mais contexte autorisé depuis la fin du split précédent
- sans fuite de target

C’est une amélioration importante et propre.

---

## 6. Les features sont encore trop “V1 techniques”
Actuellement tu as surtout :
- returns
- vol
- RSI
- ATR
- VWAP distance
- volume ratio
- sentiment simple

C’est correct, mais encore limité pour du swing daily pro.

### Je recommande d’ajouter en priorité

#### Trend / momentum
- distance à SMA/EMA 20/50/100/200
- pente EMA 20/50
- breakout 20d / 60d
- percentile du close dans le range 20/60/120 jours
- momentum 5/10/20/60 jours

#### Volatility / risk
- ATR percentile
- vol short/long ratio
- compression/expansion de range
- gap z-score

#### Relative strength
- perf relative vs SPY / QQQ / IWM
- perf relative vs secteur
- beta rolling / residual return

#### Regime
- régime marché :
  - tendance index
  - vol marché
  - breadth si dispo
- dummy earnings / macro event / FOMC si tu as la donnée

#### Liquidity / quality
- dollar volume
- rolling turnover proxy
- fréquence de `is_filled`
- flags qualité données

#### Sentiment plus utile
Plutôt que seulement `1d`, prévoir :
- 1d / 3d / 5d / 20d
- surprise sentiment
- news burst
- event recency
- missingness flag

---

## 7. L’objectif business n’est pas aligné avec les métriques d’entraînement
Aujourd’hui tu suis :
- loss
- accuracy
- precision
- recall
- auc

C’est utile, mais pour du swing cash, je suivrais surtout :

- precision sur top bucket
- hit rate conditionnel quand `proba > threshold`
- average forward return par bucket de proba
- calibration
- turnover implicite
- stability par régime

### En clair
Un modèle avec :
- 53% accuracy globale
mais
- très bon top-decile ranking
peut être plus utile qu’un modèle à 56% accuracy mal calibré.
