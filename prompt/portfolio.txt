## 2) Contexte métier à respecter

Le pipeline actuel est :

1. `selector/alpha_scanner.py` écrit `final_score` et `is_candidate`
2. `event_sentiment/signal_aggregator.py` écrit `final_score_sentiment`
3. `risk_management` lit ensuite les candidats depuis `stock_scores`

Aujourd’hui le module risque :
- charge les candidats depuis `stock_scores`
- les trie par `final_score_sentiment`
- calcule un sizing ATR ou equal-weight fallback
- applique des contraintes simples
- persiste `risk_decisions` et `portfolio_targets`

Je veux une V2 professionnelle du moteur risque, en gardant l’esprit du code existant.

## 3) Objectif V2

Implémente les 3 exigences clés suivantes :

### A. Sector neutrality
Conserver et renforcer la contrainte existante : aucun secteur ne doit dépasser 30% du portefeuille cible en notionnel brut.

### B. Correlation filtering
Ajouter un filtre de corrélation Pearson entre actions retenues :
- calculer une matrice de corrélation à partir des rendements journaliers récents
- si deux actions ont une corrélation > 0.80, ne garder que celle ayant la conviction la plus élevée
- la logique doit être greedy et déterministe
- chaque rejet doit être auditable (symbole bloquant, corrélation, raison)

### C. Kelly sizing
Ajouter un sizing Kelly fondé sur :
- la confiance modèle (`model_predictions.predicted_proba`)
- un proxy de win rate historique par symbole basé sur `model_metrics.directional_accuracy`
- fallback robuste si la donnée manque

Le sizing Kelly doit rester borné par :
- `max_position_weight`
- `max_sector_weight`
- `max_gross_exposure`
- `min_position_notional`
- circuit breaker
- et idéalement un cap ATR pour éviter l’oversizing

## 5) Design cible demandé

### 5.1 Enrichissement des inputs du moteur risque
Étends `RiskRepository` pour charger, en plus des candidats et prix :

#### a) Latest model predictions
Ajoute une méthode qui charge les dernières prédictions par symbole depuis `model_predictions`, pour une `trade_date` donnée.
Comportement souhaité :
- priorité aux prédictions du jour `trade_date`
- sinon fallback configurable à la dernière prédiction <= `trade_date`
- si plusieurs runs existent le même jour, prendre le plus récent / le plus pertinent de manière déterministe
- colonnes minimales : `symbol`, `predicted_proba`, `predicted_class`, `run_id`

#### b) Historical win rate proxy
Ajoute une méthode qui charge un proxy de win rate par symbole depuis `model_metrics`.
Règle métier :
- préférer `split_name='test'`
- fallback vers `val` si `test` absent
- utiliser `directional_accuracy` comme proxy principal
- fallback configurable (ex. 0.55) si aucune métrique disponible

#### c) Return matrix pour corrélation
Ajoute une méthode qui charge depuis `stock_bars_daily` un historique récent de prix par symbole et construit une matrice de rendements alignée par date.
Règles :
- utiliser les clôtures journalières
- calculer des rendements close-to-close
- fenêtre configurable, par défaut 60 jours de trading
- exiger un minimum d’observations communes configurable (ex. 40)
- gérer proprement NaN / symboles incomplets

### 5.2 Conviction score unifié
Définis une conviction unique utilisée pour :
- le tri initial
- le filtre de corrélation
- l’audit des décisions

Conviction proposée :
- si `predicted_proba` est disponible :
  `conviction = w1 * final_score_sentiment + w2 * predicted_proba`
- sinon :
  `conviction = final_score_sentiment`

Expose `w1` et `w2` dans `RiskConfig` avec des valeurs par défaut raisonnables, par ex :
- `score_weight = 0.40`
- `prediction_weight = 0.60`

Ajoute la validation de ces poids.

### 5.3 Filtre de corrélation
Crée une logique dédiée, proprement testable.

Spécification :
- partir des candidats triés par conviction décroissante
- conserver le premier
- pour chaque candidat suivant :
  - calculer sa corrélation avec les titres déjà retenus
  - si une corrélation > seuil (par défaut 0.80) est trouvée, rejeter le candidat
  - stocker la raison de rejet avec :
    - symbole rejeté
    - symbole bloquant
    - corrélation observée
    - seuil
- en cas de corrélation négative forte, ne pas rejeter par défaut ; on ne rejette que sur corrélation positive > seuil
- la logique doit être totalement déterministe

### 5.4 Kelly sizing robuste
Je veux une implémentation pragmatique et production-grade, adaptée aux données réellement disponibles dans ce repo.

Comme nous n’avons pas encore de table de trades réalisés par symbole, utilise cette approximation :

1. `predicted_proba` = proba de hausse court terme produite par le modèle
2. `historical_win_rate` = proxy depuis `model_metrics.directional_accuracy`
3. construire une probabilité effective :
   `p_eff = prediction_confidence_weight * predicted_proba + historical_win_rate_weight * historical_win_rate`

Ajoute ces poids à `RiskConfig`, avec validation, par exemple :
- `prediction_confidence_weight = 0.6`
- `historical_win_rate_weight = 0.4`

Puis calcule une fraction Kelly :
- `q = 1 - p_eff`
- `b = assumed_payoff_ratio` (configurable, défaut 1.5)
- `raw_kelly = p_eff - q / b`
- `fractional_kelly = max(0, raw_kelly) * kelly_fraction_multiplier`

Ajoute à `RiskConfig` :
- `assumed_payoff_ratio`
- `kelly_fraction_multiplier`
- `min_effective_probability`
- `enable_kelly_sizing`

Bornes :
- clipper `p_eff` dans `(0, 1)`
- si `fractional_kelly <= 0`, rejeter ou fallback ATR selon config
- capper la fraction à `max_position_weight`

### 5.5 Combinaison Kelly + ATR
Je ne veux pas un Kelly pur qui ignore le risque de volatilité.
Je veux une logique combinée :

- `kelly_notional = account_equity * fractional_kelly`
- `atr_risk_budget = account_equity * risk_per_trade_pct`
- `risk_per_share = atr_20 * atr_stop_multiple` si ATR dispo
- `atr_shares_cap = floor(atr_risk_budget / risk_per_share)` si ATR dispo
- `kelly_shares = floor(kelly_notional / price)`
- `proposed_shares = min(kelly_shares, atr_shares_cap)` si ATR dispo
- sinon fallback propre :
  - Kelly only si autorisé
  - sinon ATR-only
  - sinon equal-weight fallback

Je veux que la méthode de sizing finale soit auditable, ex :
- `kelly_atr`
- `kelly_only`
- `atr`
- `equal_weight`
- `rejected`
