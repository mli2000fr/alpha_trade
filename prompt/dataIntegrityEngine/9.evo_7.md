## 1. Objectif

Après l’évolution précédente (`prompt/dataIntegrityEngine/8.evo_6.md`), les trois pages métier `Risk`, `Execution` et `Corporate Actions` affichaient bien les résumés persistés, mais avec encore quelques écarts de présentation :

- mélange français / anglais dans les labels KPI ;
- titres de blocs proches mais pas totalement alignés ;
- captions générés depuis `RUN_SUMMARY_METRICS` encore hétérogènes (`Fetch`, `Pending`, `Skip`, `Fill rate`, etc.) ;
- variations de terminologie entre la page et le résumé persistant.

Le but de cette passe était volontairement limité :
**uniformiser la lecture IHM sans toucher au fond métier ni à la structure des données**.

## 3. Harmonisation appliquée

## 3.1 `ihm/services/run_summary.py`

La table `RUN_SUMMARY_METRICS` reste la source de vérité des libellés courts utilisés pour :

- les métriques affichées dans les blocs de résumé métier ;
- les captions synthétiques produits par `build_run_summary_caption(...)`.

Les libellés ont été harmonisés sur les trois domaines ciblés.

### Risk
- `Candidats` → `Cibles`
- `Positions` → `Positions cibles`
- `Notional total` → `Notional cible`

### Execution
- `Skip` → `Ignorés`
- `Fill rate` → `Taux d'exécution`

### Corporate Actions
- `Fetch` → `Récupérés`
- `Pending` → `En attente`
- `Skip` → `Ignorés`

Effet immédiat :
les captions persistés deviennent plus homogènes, par exemple :

- `cibles=5 | soumis=4 | remplis=3 | ignorés=1 | taux d'exécution=0.75`
- `en attente=6 | appliqués=4 | ignorés=1`

## 3.2 `ihm/pages/risk.py`

Ajustements de surface :

- sélecteur `Run ID` → `Run de risque`
- bloc `Résumé métier du run` → `Résumé métier persistant`
- cartes de décision :
  - `Accepted` → `Acceptés`
  - `Reduced` → `Réduits`
  - `Rejected` → `Rejetés`

Résultat :
la page utilise maintenant la même terminologie française que le résumé persistant affiché juste au-dessus.

---

## 3.3 `ihm/pages/execution.py`

Ajustements de surface :

- sélecteur `Exec Run ID` → `Run d'exécution`
- KPI principaux :
  - `Targets` → `Cibles`
  - `Submitted` → `Soumis`
  - `Filled` → `Remplis`
- `Swing only` → `Mode swing uniquement`
- `Fills` → `Exécutions`
- léger nettoyage du caption des contraintes compte :
  - `Capital`
  - `Pouvoir d'achat`
  - `Trésorerie réglée`

Le bloc `Résumé métier persistant` était déjà bien nommé ; il a été conservé comme référence commune.

---

## 3.4 `ihm/pages/corporate_actions.py`

Avant finition, les trois blocs visibles utilisaient des titres plus descriptifs mais hétérogènes (`Dernière sync`, `Dernier apply`, `Dernier run`).

Ils sont désormais alignés sur une structure commune :

- `Résumé métier persistant — Synchronisation`
- `Résumé métier persistant — Application`
- `Résumé métier persistant — Workflow`

L’historique a aussi été renommé :

- `Historique résumés corporate actions` → `Historique des résumés métier`

Résultat :
la page garde la distinction métier entre `sync`, `apply` et `run`, tout en affichant une convention de lecture identique aux pages `Risk` et `Execution`.

## 4. Convention de présentation retenue

La convention retenue pour cette passe de finition est la suivante :

### Titres de blocs
Quand un résumé provient de `run_business_summaries`, le titre de référence devient :

- `🧭 Résumé métier persistant`

avec, si besoin, un suffixe qualifiant la variante métier :

- `— Synchronisation`
- `— Application`
- `— Workflow`

### Labels KPI
- privilégier le français lorsque le sens est direct et stable ;
- conserver des formulations courtes pour rester lisible dans `metric_row(...)` ;
- utiliser la même terminologie dans la page et dans le caption généré.

### Captions
Les captions restent volontairement compacts, mais avec un vocabulaire homogène :

- `Cibles`
- `Soumis`
- `Remplis`
- `Ignorés`
- `Récupérés`
- `En attente`
- `Taux d'exécution`

---

## 5. Pourquoi cette passe reste volontairement petite

Cette évolution ne cherche pas à :

- refondre toute l’IHM ;
- factoriser toutes les pages dans un composant unique ;
- traduire l’intégralité du produit de manière globale.

Le choix retenu est pragmatique :
**corriger les incohérences les plus visibles sur les trois pages fraîchement branchées aux résumés persistés**, sans élargir inutilement le périmètre.

## 7. Conclusion

Cette passe de finition améliore la cohérence visuelle des pages `Risk`, `Execution` et `Corporate Actions` sans changer la logique métier :

- les blocs de résumés persistés suivent désormais une convention commune ;
- les labels critiques ne mélangent plus inutilement français et anglais ;

C’est une finition légère, mais utile pour rendre l’IHM plus propre après l’introduction des résumés métier persistés.
