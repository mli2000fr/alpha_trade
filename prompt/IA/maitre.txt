Mission :
concevoir et implémenter le module 3 du système Alpha-Prime :

模塊三：個股分佈式模型工廠 (Distributed Model Factory)

Objectif métier :
construire une usine d’entraînement professionnelle pour le swing trading US equities, où chaque symbole candidat peut avoir son propre modèle séquentiel entraîné à partir des données journalières nettoyées.

Choix fonctionnels imposés pour la V1 :
1. Target ML :
   - classification binaire
   - label = 1 si `future_5d_return > 0`, sinon 0
   - le modèle doit retourner une probabilité exploitable comme confidence score
2. Univers :
   - entraîner uniquement les symboles avec `stock_scores.is_candidate = 1`
3. Mode distributed :
   - un modèle indépendant par symbole
   - exécution parallèle des jobs d’entraînement
4. Features :
   - calcul à la volée à partir de `stock_bars_daily`
   - ne pas exiger de migration SQL pour la V1
5. Persistance :
   - checkpoints/scaler/config sur disque
   - registre des runs, métriques et statuts dans MySQL
6. Best model :
   - sélectionner le meilleur checkpoint sur `val_loss`
   - logger aussi `directional_accuracy`, `precision`, `recall`, éventuellement `auc`

Contraintes d’architecture :
- utiliser PyTorch Lightning ou Lightning équivalent
- support GPU si disponible, sinon fallback CPU
- modèle = LSTM + attention temporelle sur les hidden states
- attention softmax normalisée sur l’axe temporel
- pipeline strictement sans fuite de données
- split chronologique train/val/test
- scaler fit sur train uniquement
- code modulaire, testable, maintenable

Source de données :
- utiliser `stock_bars_daily` comme source principale
- utiliser `stock_scores` pour filtrer l’univers `is_candidate = 1`
- utiliser `stock_metadata` si besoin pour enrichissement
- utiliser au minimum les colonnes existantes :
  - `open`
  - `high`
  - `low`
  - `close`
  - `volume`
  - `adj_close`
  - `vwap`
  - `daily_return`
  - `is_filled`
- recalculer à la volée les features dérivées nécessaires :
  - intraday range
  - overnight gap
  - rolling volatility
  - rolling volume features
  - autres features techniques simples si justifiées
- ne pas inventer de colonnes absentes de la base
- concevoir une interface extensible pour ajouter plus tard les features sentiment du module 2

Spécifications dataset :
- un dataset par symbole
- séquence temporelle configurable, par défaut 60 jours
- horizon configurable, par défaut 5 jours
- historique minimal configurable, par défaut 252 jours
- split chronologique par symbole
- aucun shuffle entre passé et futur
- prise en charge des cas limites :
  - historique insuffisant
  - NaN
  - volumes nuls
  - lignes forward-filled
  - symboles candidats mais non entraînables

Persistance attendue :
