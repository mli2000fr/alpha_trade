Implémentation attendue :

1. Créer un service de fusion dans modelFactory/score_fusion.py :

   def compute_final_score_ml(
       final_score_sentiment: float,
       ml_predicted_proba: float,
       alpha: float = 0.6,    # calibré par backtest, sentiment pèse plus au début
   ) -> float:
       """
       Fusionne le score quant+sentiment avec la prédiction ML.
       alpha = poids du score sentiment (traditionnel)
       (1-alpha) = poids de la prédiction ML
       """
       return alpha * final_score_sentiment + (1 - alpha) * ml_predicted_proba

2. Ajouter une colonne final_score_ml dans stock_scores :
   ALTER TABLE stock_scores ADD COLUMN final_score_ml DOUBLE DEFAULT NULL;
   ALTER TABLE stock_scores ADD COLUMN ml_predicted_proba DOUBLE DEFAULT NULL;
   ALTER TABLE stock_scores ADD COLUMN ml_run_id VARCHAR(32) DEFAULT NULL;

3. Dans le pipeline quotidien V1.1, APRÈS le signal_aggregator et APRÈS le predict du module 3 :
   - Lire model_predictions du jour pour chaque symbole candidat
   - Calculer final_score_ml via le service de fusion
   - UPDATE stock_scores SET final_score_ml = :score, ml_predicted_proba = :proba WHERE symbol = :sym

4. Modifier risk_management pour OPTIONNELLEMENT lire final_score_ml :
   - Ajouter un flag use_ml_score: bool = False dans la config risk
   - Si use_ml_score=True ET final_score_ml IS NOT NULL :
       score_source = "ml_fusion"
       score = final_score_ml
   - Sinon (fallback) :
       score_source = "sentiment" (comportement V1 inchangé)
       score = final_score_sentiment
   - Le changement dans risk_management est MINIMAL : un if/else sur la source du score

5. Pipeline quotidien V1.1 :
   1. stock_screener.py           → total_score
   2. alpha_scanner.py            → final_score, is_candidate
   3. sentiment_pipeline.py       → ticker/sector features
   4. signal_aggregator.py        → final_score_sentiment
   5. python -m modelFactory --mode predict  → model_predictions + stock_scores.ml_predicted_proba
   6. python -m modelFactory --mode fuse     → stock_scores.final_score_ml (NEW)
   7. python -m risk_management --use-ml-score  → lit final_score_ml au lieu de final_score_sentiment

Contraintes :
  - Le fallback vers final_score_sentiment DOIT toujours fonctionner
  - Si model_predictions est vide pour un symbole, final_score_ml = final_score_sentiment (pas de pénalité)
  - risk_management NE DOIT PAS crasher si final_score_ml est NULL
