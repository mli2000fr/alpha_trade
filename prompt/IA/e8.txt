Implémente uniquement l’orchestrateur V1 de l’usine de modèles.

Objectif :
- récupérer l’univers `stock_scores.is_candidate = 1`
- lancer un entraînement indépendant par symbole
- paralléliser les jobs de manière raisonnable
- journaliser la progression
- tolérer les échecs isolés sans stopper tout le batch

Contraintes :
- garder la philosophie “un modèle par symbole”
- paralléliser l’exécution, pas fusionner les symboles dans un seul dataset
- rendre le nombre de workers configurable
- protéger les accès DB et la journalisation
- logs clairs par symbole et par batch

Je veux :
1. un orchestrateur de batch d’entraînement
2. un mécanisme de workers configurables
3. un résumé final :
   - total
   - success
   - failed
   - skipped
4. tests couvrant :
   - batch vide
   - plusieurs symboles
   - un symbole qui échoue et les autres continuent
   - résumé final correct

À la fin :
- montre l’API CLI ou runner minimal pour lancer l’usine
