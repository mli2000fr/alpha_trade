Implémente uniquement la couche de sortie prédictive du module 3.

Objectif :
- charger le meilleur modèle d’un symbole
- produire une prédiction de probabilité sur la dernière séquence disponible
- sauvegarder cette prédiction dans MySQL
- préparer une interface exploitable par le futur module 4

La sortie minimale doit inclure :
- symbol
- prediction_date
- target_horizon
- predicted_probability
- predicted_class
- model_run_id ou model_id
- éventuellement des métadonnées utiles

Contraintes :
- prédiction compatible avec les artefacts sauvegardés
- API stable
- pas de dépendance au module 4 encore
- prévoir que cette probabilité servira plus tard comme confidence score

Je veux :
1. un service d’inférence par symbole
2. une table SQL pour les prédictions
3. les accès DB associés
4. tests :
   - chargement artefacts
   - prédiction d’un symbole
   - persistance DB
   - gestion modèle manquant
