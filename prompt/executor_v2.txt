ATTENTION 5 — Alpaca Bracket + Trailing Stop :
  L'API Alpaca Trading v2 permet :
    - bracket orders natifs (stop_loss + take_profit comme enfants du market/limit)
    - trailing_stop orders natifs avec trail_percent
  MAIS : un bracket natif NE SUPPORTE PAS trailing stop comme leg de stop_loss.
  Le bracket natif ne permet que stop fixe ou stop-limit.
  DONC : le pattern d'exécution DOIT être un "synthetic bracket" :
    1. Soumettre l'ordre d'entrée (market ou limit)
    2. Poller / attendre le fill
    3. Après fill : soumettre séparément un trailing_stop + un limit take-profit
    4. Gérer le OCO logique côté applicatif (si l'un est rempli, annuler l'autre)
  Documente ce choix clairement dans le code avec un commentaire bloc.

OBJECTIF MÉTIER — 5 EXIGENCES CLÉS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) SYNTHETIC BRACKET ORDERS
   Entrée → attendre fill → placer trailing_stop + take_profit séparément.
   OCO logique applicatif : quand l'un des enfants est FILLED, cancel l'autre.
   Partial fills : enfants seulement sur la qty effectivement remplie.

B) PAPER / LIVE ONE-CLICK TOGGLE
   Un seul champ `broker_mode` ("paper" | "live").
   Même code path, mêmes logs, mêmes tables d'audit.
   Seule l'URL de base du broker change.

C) INSTITUTIONAL EXECUTION FEATURES
   - Pre-trade validation (market hours via pandas_market_calendars, symbole, qty > 0)
   - Idempotency par clé stable (run_id|symbol|role|side|qty|broker_mode)
   - Order lifecycle state machine (NEW → SUBMITTED → PARTIAL → FILLED/CANCELED/REJECTED/FAILED)
   - Retry réseau borné (max_order_retries) avec exponential backoff
   - Cancel/replace enfants si la qty fillée change (partial fill progressif)
   - End-of-day reconciliation broker positions vs portfolio_targets
   - Kill switch : circuit breaker actif OU clock fermée OU erreurs critiques répétées
   - Mode dry_run : persiste les intents/events mais AUCUN appel broker
   - Recovery journal : à la reprise, détecter les intents déjà soumis et ne pas re-soumettre
   - Slippage monitoring : alerter si fill_price vs entry_price > max_slippage_bps

D) POST-TRADE AUDIT & TCA (Transaction Cost Analysis)
   - Persister chaque événement du lifecycle dans execution_events
   - Calculer slippage_bps = (avg_fill_price - entry_price) / entry_price × 10000
   - Calculer implementation_shortfall = (avg_fill_price - decision_price) × qty
   - Stocker dans execution_fills les métriques post-trade
   - Résumé TCA par run dans le log final

E) ORDER THROTTLING & RATE GOVERNANCE
   - Ne pas soumettre plus de execution_batch_size ordres simultanés
   - Respecter un inter_order_delay_ms configurable (Alpaca rate limit = 200 req/min)
   - Si 429 reçu, backoff exponentiel automatique

@dataclass(frozen=True, slots=True)
class ExecutionConfig:
    # --- Mode ---
    broker_mode: str = "paper"              # "paper" | "live"
    dry_run: bool = False

    # --- Entry order ---
    entry_order_type: str = "market"        # "market" | "limit"
    limit_price_buffer_bps: int = 10        # buffer au-dessus de entry_price pour limit

    # --- Bracket legs ---
    profit_taker_pct: float = 0.08          # +8% take profit
    trailing_stop_pct: float = 0.05         # 5% trailing stop
    trailing_stop_type: str = "percent"     # "percent" (Alpaca trail_percent)

    # --- Execution ---
    allow_fractional_shares: bool = False
    max_slippage_bps: int = 30              # alerte si slippage > 30 bps
    max_order_retries: int = 3
    retry_base_delay_seconds: float = 1.0   # exponential backoff base
    inter_order_delay_ms: int = 350         # 200 req/min ≈ 300ms par req + marge
    poll_interval_seconds: float = 2.0
    fill_timeout_seconds: int = 120
    cancel_timeout_seconds: int = 30

    # --- Market hours ---
    market_clock_skew_seconds: int = 5
    allow_outside_rth: bool = False
    market_calendar_name: str = "NYSE"      # pour pandas_market_calendars

    # --- Safety ---
    enable_kill_switch: bool = True
    max_consecutive_failures: int = 3       # kill switch après N échecs consécutifs
    execution_batch_size: int = 20

    # --- Reconciliation ---
    reconcile_after_submit: bool = True
    reconcile_tolerance_shares: int = 0     # tolérance delta avant action

    # --- TCA ---
    enable_tca: bool = True

    def __post_init__(self) -> None:
        if self.broker_mode not in ("paper", "live"):
            raise ValueError("broker_mode doit être 'paper' ou 'live'.")
        if self.entry_order_type not in ("market", "limit"):
            raise ValueError("entry_order_type doit être 'market' ou 'limit'.")
        if not (0 < self.profit_taker_pct < 1):
            raise ValueError("profit_taker_pct doit être dans ]0, 1[.")
        if not (0 < self.trailing_stop_pct < 1):
            raise ValueError("trailing_stop_pct doit être dans ]0, 1[.")
        if not (0 <= self.max_slippage_bps <= 500):
            raise ValueError("max_slippage_bps doit être dans [0, 500].")
        if self.max_order_retries < 0:
            raise ValueError("max_order_retries doit être >= 0.")
        if self.retry_base_delay_seconds <= 0:
            raise ValueError("retry_base_delay_seconds doit être > 0.")
        if self.inter_order_delay_ms < 0:
            raise ValueError("inter_order_delay_ms doit être >= 0.")
        if self.poll_interval_seconds <= 0:
            raise ValueError("poll_interval_seconds doit être > 0.")
        if self.fill_timeout_seconds <= 0:
            raise ValueError("fill_timeout_seconds doit être > 0.")
        if self.cancel_timeout_seconds <= 0:
            raise ValueError("cancel_timeout_seconds doit être > 0.")
        if self.execution_batch_size < 1:
            raise ValueError("execution_batch_size doit être >= 1.")
        if self.max_consecutive_failures < 1:
            raise ValueError("max_consecutive_failures doit être >= 1.")

    def is_paper(self) -> bool:
        return self.broker_mode == "paper"

    def is_live(self) -> bool:
        return self.broker_mode == "live"

def build_entry_intents(
    targets: list[ExecutionTarget],
    config: ExecutionConfig,
    exec_run_id: str,
) -> list[OrderIntent]:
    Un intent par target_shares > 0.
    side = "buy"
    order_type = config.entry_order_type
    limit_price = entry_price × (1 + limit_price_buffer_bps / 10000) si limit
    intent_role = "entry"
    parent_intent_id = None
    decision_price = entry_price
    idempotency_key = hashlib.sha256(f"{risk_run_id}|{symbol}|entry|buy|{qty}|{broker_mode}".encode()).hexdigest()[:32]
    intent_id = uuid.uuid4().hex[:16]

def build_take_profit_intent(
    parent: OrderIntent, fill_qty: float, avg_fill_price: float, config: ExecutionConfig,
) -> OrderIntent:
    side = "sell", order_type = "limit"
    limit_price = round(avg_fill_price × (1 + profit_taker_pct), 2)

    def execute_run(self, risk_run_id: str | None = None, trade_date: date | None = None) -> dict[str, int]:
        Phase 1 — Init : exec_run_id, insert_execution_run, emit RUN_STARTED
        Phase 2 — Pre-flight : load targets, circuit breaker, market clock
        Phase 3 — Build intents, filter duplicates
        Phase 4 — Submit entries (batched + throttled, dry_run simulated)
        Phase 5 — Poll fills, compute TCA per fill, slippage alerts
        Phase 6 — Submit children (synthetic bracket), emit CHILDREN_SUBMITTED
        Phase 7 — OCO monitoring
        Phase 8 — Reconciliation broker vs targets
        Phase 9 — TCA summary
        Phase 10 — Finalize : RUN_COMPLETED, return metrics
