Construire à partir de maintenant un historique prospectif, causal, append-only et PIT de données analystes gratuites, principalement via Yahoo/yfinance, afin de tester plus tard des features directionnelles capables d’aider à distinguer :

dans le pool Oracle.

2. Principe PIT fondamental

Pour chaque donnée récupérée :

observed_at

= moment réel où notre collecteur a observé Yahoo.

available_at

= moment à partir duquel cette donnée est autorisée pour une décision de trading.

Contrat obligatoire :

source.available_at <= decision_cutoff

Exemple :

décision close J : 16:00 ET
collecte Yahoo : 18:30 ET

alors :

le snapshot collecté à 18:30
est INTERDIT pour la décision de J

Il ne devient utilisable qu’à la prochaine session de décision.

Aucun raccourci basé uniquement sur :

DATE(snapshot)

8. Append-only strict

Ces tables doivent représenter :

ce que le système connaissait réellement à chaque date

Exemple :

2026-08-29 EPS FY = 4.25
2026-08-30 EPS FY = 4.18

La DB doit contenir :

29/08 → 4.25
30/08 → 4.18

Interdiction :

UPDATE ancienne valeur à 4.18

Une nouvelle observation crée une nouvelle ligne.

11. Fiscal rollover

Point critique.

Yahoo utilise des horizons relatifs :

0q
+1q
0y
+1y

0q aujourd’hui peut représenter une période fiscale différente de 0q après publication des résultats.

Une variation :

CURRENT_QUARTER J
vs
CURRENT_QUARTER J-20

n’est une vraie révision que si :

même fiscal_period_end

Si Yahoo ne fournit pas l’identité fiscale exacte :

relative_horizon_only = true

et les révisions traversant un rollover doivent être :

NULL

Pas de fausse révision.
